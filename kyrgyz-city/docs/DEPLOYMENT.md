# Публикация в интернете

Пока проект запускается локально. Публичной ссылки нет, хостинг не создан, данные никуда не отправлялись. Следующие действия выполняет владелец проекта, когда решит публиковать игру. Пароли в чат не нужны.

Перед публикацией проверьте согласие Шабданова Эмира, Дженишова Аликхана и Исламбекова Алишера на размещение их имён и названия лицея. Проведите редактуру кыргызского преподавателем и реальные браузерные проверки из TESTING.md. На странице «О проекте» сейчас честно отмечен черновой статус материалов.

## Вариант с Docker на хостинге

Нужен хостинг, который запускает Python/FastAPI или Docker-контейнер, например Render, Railway, Fly.io или собственный VPS. Условия бесплатных тарифов меняются: проверьте лимиты и возможную плату до запуска. Игра не использует платные API, но провайдер может брать деньги за сервер.

1. Создайте свой репозиторий проекта. Не добавляйте `.venv`, `node_modules`, `.env`, пароли и личные данные. Подготовленные `.gitignore` и `.dockerignore` исключают эти файлы.
2. В панели хостинга создайте Web Service и выберите Dockerfile из корня проекта.
3. Dockerfile сам установит Node.js-зависимости, соберёт frontend и перенесёт только готовую сборку в Python-образ. Затем установит FastAPI и запустит Uvicorn. Порт берётся из переменной `PORT`, по умолчанию 8000.
4. Настройте health check: `/api/health`. База данных и отдельное файловое хранилище для этой версии не нужны.
5. Дождитесь успешного deployment. Скопируйте адрес, выданный провайдером. Установите переменную окружения `PUBLIC_ORIGIN` равной этому адресу, например `https://имя-проекта.провайдер.example`, без завершающего `/`. Перезапустите сервис.
6. Проверьте главную страницу, `/game`, `/lessons/ru?text=1`, `/lessons/en?text=1`, `/about`, `/privacy`, `/robots.txt`, `/sitemap.xml` и `/api/health`.
7. Проверьте микрофон через HTTPS и игру на телефоне. Не используйте HTTP для удалённого микрофона: браузеры обычно разрешают его только на HTTPS и localhost.

Dockerfile подготовлен, но сборка Docker в текущей среде не выполнялась. Фактический запуск контейнера входит в проверку выбранного вами хостинга.

## Без Docker

На сервере должны быть Python 3.11+ и Node.js 22.12+. Из корня проекта:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cd frontend
npm ci
npm run build
cd ..
.venv/bin/python -m uvicorn main:app --host 0.0.0.0 --port 8000
```

Собранные файлы находятся в `static/app`. FastAPI сам отдаёт их вместе с API и Jinja2-шаблонами, поэтому отдельно загружать frontend на второй домен не требуется. Если ваш хостинг предоставляет только Python, собирайте frontend на своём компьютере и загружайте `static/app` вместе с остальным проектом. Эта папка исключена из Git по умолчанию; для такого способа доставки используйте артефакт сборки или осознанно добавьте её в выбранный deployment-пакет.

Для VPS настройте systemd или аналог для перезапуска Uvicorn, а перед ним — Caddy либо Nginx. Caddy может получать сертификаты Let's Encrypt автоматически. Откройте наружу 80/443 для reverse proxy, Uvicorn держите на loopback. Не запускайте `--reload` в production. Администрирование VPS и настройку firewall выполняйте только понимая изменения.

## Домен и HTTPS

Домен необязателен: адрес хостинга уже может быть публичным и поддерживать HTTPS. Собственный домен удобен для узнаваемого названия. Купите его у регистратора, добавьте в настройках хостинга и скопируйте именно выданные хостингом DNS-записи. Это могут быть CNAME или A/AAAA; не угадывайте IP.

Дождитесь подтверждения домена и выпуска сертификата. Установите `PUBLIC_ORIGIN=https://ваш-домен`. При смене домена старый localStorage не переносится автоматически. Хостинг должен разрешать публичный доступ; это настраивается в его панели. Для публичной игры не включайте обязательную регистрацию посетителей.

## Индексация Google

Сервер отдаёт обычный HTML со словами и примерами по `/lessons/ru`, `/lessons/en`, `/lessons/ky` и `/lessons/{язык}/{урок}`. Поисковику не нужно запускать 3D. В HTML есть title, description, Open Graph, hreflang. При заданном `PUBLIC_ORIGIN` появляются canonical и структурированные данные WebApplication, а sitemap содержит абсолютные адреса. Без публичного адреса sitemap намеренно пуст, чтобы не публиковать вымышленные URL.

1. Убедитесь, что сайт отвечает без пароля, ошибки и блокировки поисковиков.
2. Откройте Google Search Console со своим Google-аккаунтом.
3. Добавьте свойство «Домен» и подтвердите владение DNS TXT-записью из Search Console. Для адреса провайдера можно использовать свойство «Префикс URL» и предлагаемый Google метод проверки.
4. В разделе Sitemaps отправьте `https://ваш-домен/sitemap.xml`.
5. Проверьте индексируемые страницы через «Проверка URL». Для важных уроков можно запросить индексацию.
6. Следите за ошибками и добавляйте полезный отредактированный контент. SEO не гарантирует ни немедленную индексацию, ни первую страницу поиска.

Если проверка Google требует HTML-файл, положите его в `static/` и настройте отдельный маршрут с точным URL либо используйте DNS-проверку. Нельзя публиковать секреты аккаунта или выдавать сгенерированный файл за подтверждение владения без действий владельца.

## Обновление

Измените исходники и JSON, выполните тесты и сборку, затем запустите новый deployment тем же способом. Сохраняйте предыдущую версию для отката. Не меняйте ID слов и миссий без миграции сохранений. Обычное обновление файлов не должно удалять прогресс в браузере. После установки новых Python-зависимостей обновите `requirements.txt` и переустановите зависимости на хостинге. Продвижение сайта, домен, аккаунты хостинга и публичный запуск остаются под вашим управлением.
