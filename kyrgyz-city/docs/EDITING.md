# Редактирование Kyrgyz City

Все пути указаны от папки проекта. Перед правками сделайте копию папки. JSON редактируйте в VS Code или другом редакторе UTF-8; сохраняйте запятые и кавычки. После правок запустите проверки из TESTING.md.

## Словарь

Файл `backend/content/vocabulary.json` — единственный источник слов для API, игры и HTML-уроков. Пример записи:

```json
{
  "id": "home-3",
  "ky": "Терезе",
  "translations": {"ru": "Окно", "en": "Window", "ky": "Терезе"},
  "category": "home",
  "level": "A0",
  "example": "Терезе чоң.",
  "context": {"ru": "Мой дом", "en": "My home", "ky": "Менин үйүм"},
  "grammar": null,
  "audio": null,
  "location": "home",
  "review_status": "draft"
}
```

Для нового слова добавьте объект с новым постоянным ID. Перевод меняется в `translations`; пример — в `example`. Для нескольких значений используйте понятную строку с разделителем, например `Дом / жилище`, и поясните значение в примере. Менять существующие ID нежелательно: они участвуют в сохранениях.

`review_status: "reviewed"` ставьте только после реальной проверки преподавателем. Зафиксируйте редактора, дату и источник в отдельном журнале `docs/CONTENT_REVIEW.md`, когда такая проверка состоится. Сейчас все 160 записей имеют статус `draft`.

Чтобы добавить разрешённую запись носителя, положите её в `static/audio/` и укажите `audio: "/static/audio/имя-файла.mp3"`. Сохраните разрешение и источник в ASSETS.md. Кнопка карточки поддерживает такое воспроизведение; сейчас у всех слов `audio: null`. Специального аудиоплеера со скоростью и громкостью для внешних записей пока нет.

## Уроки

`backend/content/lessons.json` содержит 18 уроков. Добавьте объект с уникальным `id`, названием на трёх языках, существующим ID локации, `word_ids`, уровнем сложности, длительностью, учебной заметкой, массивом `sentence` и переводом предложения `sentence_translation`.

Каждое слово из `word_ids` получит упражнение, чередующее перевод, обратный перевод и ввод. Отдельный шаг учит порядку слов. Используйте хотя бы четыре слова с различающимися значениями, чтобы варианты ответов были содержательными. Убедитесь, что предложение действительно связано с темой урока. Все уроки автоматически появляются в интерфейсе, API и серверных HTML-страницах.

## NPC и диалоги

Имя, роль и диалог NPC находятся в `backend/content/locations.json` в `npc` и `dialogue`. Меняйте все три перевода роли; имена собственные обычно не переводятся.

`backend/content/dialogues.json` содержит граф реплик. У каждого узла есть `id`, `text` на кыргызском, `translation`, `options` и объяснение. Правильный ответ ведёт в `next`; `next: null` завершает разговор. Неправильный ответ оставляет игрока на текущем узле, показывая `explanation`. Шаблон `{name}` подставляет игровое имя.

Учебная логика поддерживает граф, но текущий интерфейс отображает индикатор на три реплики. Если вы добавляете диалог другой длины, обновите индикатор в `components/Learning.tsx`. Не превращайте неверный вариант в бессмысленную фразу ради случайной ловушки. Сейчас для каждого из 10 собеседников есть одна ситуация, повторяемая без новых XP.

## Миссии

Файл `backend/content/quests.json`: ID, заголовок на трёх языках, награда `xp` и последовательность `steps`. Шаги реагируют на:

- `visit`: вход в локацию, `target` — ID локации;
- `dialogue`: завершение диалога, `target` — его ID;
- `lesson`: завершение урока, `target` — его ID;
- `word`: изучение конкретного слова, `target` — ID слова.

Отслеживается только выбранная миссия. Старые действия не засчитываются задним числом: их можно повторить. За повторение урока или диалога не начисляется новая базовая награда, но событие для текущей миссии поступает. Награда за миссию выдаётся один раз. Добавляя новые типы событий, меняйте `state/progress.ts` и места отправки событий в App.tsx, затем тестируйте порядок шагов.

## Новая локация

1. Добавьте запись в `locations.json`: переводы, `position: [x,z]`, `size: [ширина,глубина]`, цвет, тип здания, точку входа, NPC, ID диалога, `word_ids`.
2. Координаты мира ограничены примерно от -48 до +48. Точка входа должна быть за стеной, на свободном месте, связанном с тротуаром. Коллизии берутся из положения и размера здания автоматически.
3. Файл `frontend/src/game/Models.tsx` создаёт внешний вид. Для нового типа здания добавьте отличительные детали; не копируйте одинаковую коробку. Для парка и остановки сделаны отдельные типы без закрытого внешнего корпуса.
4. Файл `game/shared.ts` задаёт предметы внутренней сцены: ID слова, тип модели, координаты. В `CityScene.tsx`, компонент `Item`, находятся модели предметов. Существующие типы можно переиспользовать.
5. Добавьте подходящий урок и диалог. Не оставляйте посещаемое здание без них.
6. Проверьте маршрут к входу, мебельные коллизии, имя NPC и все три языка. При расширении города за границы обновите навигацию, покрытие земли, дороги и мини-карту, а не только координаты здания.

## Внешний вид, UI и авторы

- `frontend/src/styles.css`: палитра, размеры, адаптивные правила 650/900/1150px и оформление интерфейса.
- `frontend/src/game/Models.tsx`: геометрия зданий и персонажей.
- `frontend/src/game/CityScene.tsx`: свет, камера, город, интерьеры, движение.
- `frontend/src/localization/index.ts`: все основные тексты UI. Новый ключ должен иметь три перевода.
- `frontend/src/App.tsx`: расположение панелей и разделов.
- Информация об авторах есть в локализации, блоке `authors` в App.tsx, `main.py` для noscript и README.md. При изменении обновляйте эти места согласованно. Не добавляйте несуществующие роли и должности.

После правок frontend выполните `npm run build`. После правок JSON или Python перезапустите FastAPI либо используйте `--reload` в режиме разработки.
